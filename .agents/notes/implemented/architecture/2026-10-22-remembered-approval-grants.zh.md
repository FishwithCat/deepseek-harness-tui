# Agent Note: 记住按工具的审批授权

Status: implemented

[English](2026-10-22-remembered-approval-grants.md) | 中文

## 问题

[TUI 的委派审批应答器](2026-10-22-interactive-delegated-approvals.zh.md)对每个请求只提供一次性决定。因此，反复对同一工具升权的会话每次调用都会弹出提示，而子代理的询问在根代理已批准同一工具后仍会再次提示。审批 seam 没有持久记住决定的方式：其闭合结果词汇是一次性的，而界面本地的集合无法回放、无法到达子代理的审计，也会绕过服务的 `never` 策略。

## 决定

### 授权是持久的会话状态

`ApprovalService.grant(session, toolName)` 追加一条 `approval/grant` 事件。`isGranted(agent, toolName)` 读取 Agent 自身会话以及通过 `parentSession` 可达的每个存活祖先；祖先消失即结束遍历。对同一会话中的同一工具重复授权不会追加任何内容。该事件是必需的第一方记录，因此不支持授权的构建会拒绝包含它的会话，而不是静默地再次提示。授权可以在轮次外记录，因为该事件是独立的；`request()` 保持自己的轮次封闭要求。

### 授权在服务内部检查

`request()` 在 `never` 检查之后、应答者分发之前，把被覆盖的询问解析为 `allowed-once`。`never` 始终优先，授权也不能让应答者看到它已无权看到的询问。被覆盖的决定追加现有的 `approval/decided` 事件，并带有 `remembered: true`。闭合的 `ApprovalOutcome` 词汇不变，因此工具、沙箱升权、ACP 及其分支继续使用同一个批准值。

### TUI 在自己的根 Agent 上记录

`installApprovalAnswerer` 在「允许一次」和「拒绝」旁增加「始终允许 <工具>」。选择它会调用 `grant(owned.session, toolName)` 并返回 `allowed-once`；因此无论提示来自根代理还是子代理，授权都覆盖整个应用树。标签会指出工具，提示描述会说明「会话及其子代理」的范围。`TerminalTranscript` 把带 `remembered` 的决定渲染为 `allowed always`，无论是在根转录还是子代理的 watch 查看器中。

模型不会看到新的上下文：授权改变的是哪些询问会到达应答者，而不是发起请求的消费方最终得到的允许工具结果。授权没有撤销 API 或 TUI 控制；把策略切换为 `never` 会抑制所有询问。

## 考虑过的替代方案

**在 `ApprovalOutcome` 中增加 `allowed-always`。** 拒绝：结果是工具分发、沙箱升权、ACP 与测试消费的闭合 wire 词汇；新增值会迫使每个分支修改，旧读取方也无法解释新的审计值。改用 `remembered` 标记现有的允许决定。

**把授权保存在 TUI 本地集合中。** 拒绝：恢复会话会丢失授权，子代理 watch 查看器会显示它无法解释的授权，而且 TUI 之外的请求仍会弹出提示，即使该会话的应答者已经允许该工具。

**只授权发起询问的子代理。** 拒绝：请求的行为是根代理的「始终允许」到达其子代理；记录在应用的根代理上可以为整棵树提供一套策略，也使子代理的选择同样明确。

**按精确工具调用或参数授权。** 拒绝：`ApprovalRequest` 有意不携带参数，把调用的参数体复制成第二个持久身份会让授权与已记录的工具调用发生漂移。

**让任何应答者通过返回新结果来授权。** 拒绝：机器应答者会因此隐式创建持久状态。TUI 显式调用 `grant`，服务在分发前评估已存储的授权。

## 后果

- 授权覆盖该工具在会话剩余时间及其存活后代中门控的所有操作；它比单个升权目标更宽，且没有撤销控制。
- 旧构建会拒绝包含必需 `approval/grant` 事件的会话；它不会静默丢弃授权。支持授权的构建会把不含授权的旧日志视为无授权，并保留其已记录的一次性决定。
- 每个被覆盖的询问仍会追加 `approval/asked` 与 `approval/decided`，保持审计完整。
- TUI 的提示现在有三个选项；「始终允许」是唯一记录持久状态的路径。

## 验证

- `dsh-user-approval` 证明幂等授权、空名称拒绝、带 `remembered` 的自动 `allowed-once`、`never` 优先、在作答过程中记录的授权、存活后代、多个祖先，以及父级或注册表缺失。
- `dsh-tui-app` 证明根代理的「始终允许」到达后续根询问与子代理，子代理的「始终允许」到达根代理，且转录渲染 `allowed always`。
- 持久化记录 `2026-10-22-approval-grants` 把新事件与可选决定字段确认为同版本。

# Agent Note: TUI 推理强度切换

Status: implemented

[English](2026-09-11-tui-reasoning-effort.md) | 中文

## 问题

每条确切的模型路由都会声明其适配器接受的推理强度，`installModelSelection` 会把当前选择所指定的那一个应用到下一步的请求配置上。[fork 终端界面](../architecture/2026-09-11-fork-terminal-surface.zh.md)此前无法查看或修改它：`/model` 只切换路由，页脚只在显式选择过之后才显示强度，而所有请求都使用部署默认值或 `agent-default-model` 设置提供的值。终端用户若想为困难任务提高强度、或为延迟敏感的任务降低强度，就只能离开当前会话。

## 决策

**`/effort` 是一个与 `/model` 形态相同的应用内命令。** 不带参数时，它打开同样的普通行选择器（`src/views.ts` 的 `PromptPanel`），按适配器顺序列出 `ctx.llm.resolveModelInfo(provider, model).reasoning` 声明的强度，并显示每个强度的适配器名称与描述。带参数时，它匹配某个已声明的强度 id 并直接应用；未匹配的 id 会报告 `expected one of <ids>`；适配器未声明推理元数据的路由会如实报告并且不做任何修改。

**只有当适配器未声明默认强度时，选择器才提供 `Provider default` 选项。** 该选项会清除显式强度，使请求省略该字段——这与指定任何已声明强度都是不同的请求。若适配器声明了默认值，指定该强度本身就是同一个请求，因此不再单独提供清除项——这正是 ACP 界面的 `reasoning_effort` 选项已经遵循的规则，两个界面的选项集合因此保持一致。

**应用强度改写的是实时选择，而不是设置。** `applyEffort` 对当前路由调用 `TuiSession.selectModel({ provider, model, reasoningEffort })`，于是 `installModelSelection` 会把它绑定到下一次组装出的请求，页脚的 `模型 • 强度` 标签也在同一次刷新中重绘。不会写入设置文档，因此该选择只对当前会话生效，不影响下一个 Agent。

**`/model` 在切换路由时会清除强度。** 新路由自身的默认值随之生效。沿用旧强度可能指名新模型并不接受的强度，而 `resolveCallConfig` 会在任何 provider I/O 之前拒绝不受支持的显式强度，于是沿用的值会让下一轮直接失败，而不是干净地完成切换。

## 备选方案

**把强度并入 `/model` 的选择器做成第二步。** 一个命令先问路由、再问强度。它没有被采用，因为两者的变更彼此独立：会话中途提高强度很常见，而切换模型并不常见，合并流程会让常见操作走最长的路径。

**把命令命名为 `/reasoning` 或 `/thinking`。** 这两个名字在行文中更自然。它们没有被采用，因为该接缝、ACP 选项、设置字段与页脚都把该值称为 reasoning effort，跨界面统一用词比省一个词更有价值。

**始终提供 `Provider default` 清除项。** 只有当适配器未声明默认值时，清除才是一个不同的请求；在已声明默认值旁边再给出清除项，会产生两个请求完全相同的选项，在用户看来就是选择器的缺陷。

**同时接受强度的显示名与 id。** `/effort High` 比 `/effort high` 更友好。它没有被采用，因为 id 才是适配器接受的不透明取值，而名称只是可能重复、可能变化的展示元数据；同时匹配两者需要第二条查找规则和一套歧义处理策略，只为省下五个字符的输入。

## 后果

终端用户现在可以在会话内切换推理强度，并在页脚读到结果；选择器的选项集合恰好等于被路由适配器所声明的集合——只支持 `off` 的模型只提供该项，没有推理元数据的模型会如实报告，而不是显示空列表。

每次调用都会通过 `ctx.llm.resolveModelInfo` 解析被路由模型的元数据（对所有随附适配器而言都是同步查找）；切换模型会清除强度而不是沿用，因此希望在新模型上保持同样强度的用户需要再选择一次。

## 测试

`tests/tui-app.spec.ts` 通过一个声明 DeepSeek 形态强度集合的脚本化适配器驱动该命令：选择器会应用所选强度且页脚显示 `test-model • off`；被取消的选择器不应用任何内容，其行也会从合成后的备用屏幕画面中消失；`/effort <id>` 直接应用并拒绝未知 id（同时列出可接受的值）；未声明推理的路由会如实报告；没有默认强度的路由提供 `Provider default`，清除后报告新的状态为 provider default。同一文件还覆盖了 fixture 现在可以触达的 `/model` 各条路径：选择器、其取消、`/model provider/model` 直接输入，以及格式错误的路由。
